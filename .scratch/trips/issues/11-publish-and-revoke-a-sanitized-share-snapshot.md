# 11: Publish and revoke a sanitized Share Snapshot

**What to build:** Let a human publish a read-only itinerary without granting access to the live Trip Document. Before publishing or updating, show the exact allowlisted Share Snapshot that will leave the private Library. Publishing creates an unguessable capability link to an immutable snapshot revision; later private edits remain private until the owner explicitly previews and updates the shared version. Revocation immediately removes public access.

**Blocked by:** 05: Plan with Library sources and Unscheduled entries.

**Status:** done

- [x] Snapshot preparation is owned by the Trips module and includes only owner-selected day labels, stop names, public notes, timings, durations, addresses/map coordinates, public source links, timezone, and public trip context.
- [x] Private Item captions, Library notes, private trip notes, internal identifiers, agent instructions, changesets, account identity, and non-public provenance are excluded by construction rather than removed in the public renderer.
- [x] The human sees the exact sanitized preview before Publish or Update Shared Version and may cancel without creating or changing a public snapshot.
- [x] Capability tokens are unguessable, stored only as hashes, not enumerable, and excluded from indexes and private-agent read tools.
- [x] Public viewers need no account, receive a responsive read-only page with Last Updated and timezone, and cannot mutate, comment, invoke private WebMCP tools, or reach the live Trip Document.
- [x] Private Trip Document edits do not change the published snapshot until an explicit human update. Revocation makes the existing capability return no itinerary payload; republishing after revocation uses a new token.
- [x] Publish, update, and revoke are human-only operations with authenticated Library authorization. No WebMCP tool can perform them.
- [x] Module/security tests cover the allowlist, private-field exclusion, immutable revisions, token hashing, non-enumeration, revocation, Library isolation, and absence of live-document access. HTTP/browser tests cover preview/cancel/publish/update/revoke, mobile public rendering, and forbidden agent actions. Relevant existing tests, typecheck, and build remain green.

## Comments

`server/trips/share.ts` owns the seam: `prepareShareSnapshot(db, trip)` is the single allowlist (title/destination/dates/timezone, day labels, stop names, public notes, time windows, durations, outside/item source URLs, Place ancestry + lat/lng only when the Place carries them, holes as unresolved requests). Draft stops and broken references stay out; privateNotes, captions, ids, provenance, advisories, inferences, and context never enter the snapshot object. Schema v17 adds `trip_share_snapshots` (token_hash UNIQUE, snapshot_json, revoked_at, FK cascade). Publish = one call that mints a fresh 32-byte base64url token, stores only its SHA-256 hash, and replaces any previous row — update and republish-after-revoke are the same path, so an old link always dies and the raw token exists only in the publish response (the owner's tab keeps it in sessionStorage for Copy link). Revoke stamps revoked_at; findSharedSnapshot treats revoked/unknown/wrong-token identically. Public page is `/s/:token` outside `/api/` (no session, no cookie), server-rendered static HTML with Locus-native colors, Last Updated, timezone, zero scripts — no mutation, comments, or WebMCP by construction. HTTP: GET share state, POST preview (writes nothing)/publish/revoke, all session+CSRF human routes; WebMCP tool list unchanged (test now forbids share-named tools explicitly). UI: Share → preview panel → Publish/Cancel; shared chip, Update shared version (preview first), share link, confirm-Revoke.

Commands: `npx tsc --noEmit`, `npm test` (345 pass; three consecutive clean full runs), `npm run build`, `npx vite build` before browser tests.
