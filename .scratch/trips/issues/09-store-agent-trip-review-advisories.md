# 09: Store agent trip-review advisories through WebMCP

**What to build:** Let a user explicitly ask their visible browser agent to review the current Trip Document for travel feasibility, strain, or missing planning information. Locus supplies only the exact saved Trip Document; it does not fetch routes, invent thresholds, gather background location data, or enrich the review. The agent may call a bounded WebMCP write tool to save clearly labelled advisory opinions tied to exact days, stops, or legs so the user can revisit them later.

**Blocked by:** 06: Show Overview, Schedule, and empty-day states; 08: Expose the exact itinerary through Trips WebMCP.

**Status:** done

- [x] `record_trip_review` is available only while the owning Trip Document is visible and only after an explicit user request to review it.
- [x] The tool accepts the expected Trip Document revision, a client mutation id, and a bounded set of advisory flags. Each flag declares a category (`travel_feasibility`, `strain`, or `missing_information`), severity, concise opinion, rationale, and valid references to the relevant day/stops.
- [x] The adapter provides no hidden route durations, distance matrix, inferred fitness profile, external search results, or product-defined daily-load threshold. The agent reviews only fields returned by `get_trip` and general reasoning prompted by the user.
- [x] Review payloads cannot persist new outside facts, route data, source URLs, scraped text, coordinates, reservations, or Library entities. Factual itinerary changes must use the normal exact-change workflow and user authorization.
- [x] Every saved flag is visibly labelled Agent opinion with actor, time, reviewed Trip Document revision, rationale, and referenced itinerary objects. It is never presented as deterministic validation or verified travel advice.
- [x] The user can dismiss a current advisory through a human changeset. Prior versions remain understandable in Trip history.
- [x] A stale, invalid, over-bounds, cross-Library, or partially invalid review is rejected atomically; retries with the same client mutation id are idempotent.
- [x] Opening a trip never requests or refreshes an agent review automatically. Editing the itinerary marks affected advisories as based on an older revision rather than silently rewriting them.
- [x] Real-database tests cover storage, revision linkage, dismissal/history, stale and idempotent behavior, invalid references, bounds, and rejection of external-fact fields. WebMCP/browser tests cover explicit invocation, visible advisory rendering in Overview/Day/Schedule, no automatic call, lifecycle cleanup, and clear separation from deterministic health. Relevant existing tests, typecheck, and build remain green.

## Comments
